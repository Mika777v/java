## 4. 状態遷移図

### 4.1 割り当ての状態(`task_assignments.status`)

```mermaid
stateDiagram-v2
    [*] --> 未着手: 割り当てる
    未着手 --> 対応中: 状態を変える
    未着手 --> 完了: 状態を変える<br/>(完了日時を記録)
    対応中 --> 完了: 状態を変える<br/>(完了日時を記録)
    対応中 --> 未着手: 状態を変える
    完了 --> 対応中: 状態を変える<br/>(完了日時を消す)
    完了 --> 未着手: 状態を変える<br/>(完了日時を消す)
    未着手 --> [*]: 割り当て解除・ユーザー/タスクの削除
    対応中 --> [*]: 割り当て解除・ユーザー/タスクの削除
    完了 --> [*]: 割り当て解除・ユーザー/タスクの削除
```

- どの状態からどの状態へも変えられます(管理者はユーザー詳細から、新入社員はマイページから)
- **「期限切れ」は保存された状態ではなく、表示するときに判定** します: 期限が今日より前 かつ 完了ではない
- 完了 → 完了 のように同じ状態を選び直しても、最初の完了日時は変わりません
- サブ項目があるタスクは、チェックでも状態が変わります(次の 4.1.1)

#### 4.1.1 サブ項目のチェックによる自動の変化

```mermaid
stateDiagram-v2
    未着手 --> 対応中: 1 つチェック
    未着手 --> 完了: 全部チェック(項目が 1 つだけのとき)
    対応中 --> 完了: 全部チェック<br/>(完了日時を記録)
    完了 --> 対応中: チェックを外す<br/>(完了日時を消す)
```

- チェックが 0 個になっても「未着手」には戻しません(完了からの場合は「対応中」、それ以外は今のまま)
- サブ項目の追加・削除だけでは状態は変わりません

### 4.2 専用URLの状態(新入社員ごと)

```mermaid
stateDiagram-v2
    [*] --> 未発行: ユーザー登録
    未発行 --> 有効: 発行
    有効 --> 有効: 再発行<br/>(古い URL は使えなくなる)
    有効 --> 期限切れ: 有効期限(60 日)を過ぎる
    期限切れ --> 有効: 再発行
    有効 --> 未発行: 無効化
    期限切れ --> 未発行: 無効化
    有効 --> 未発行: 役割を管理者に変更
    期限切れ --> 未発行: 役割を管理者に変更
```

| 状態 | DB(`users`) | URL を開いたとき | ユーザー詳細の表示 |
|---|---|---|---|
| 未発行 | `access_token_hash` が NULL | — | 「まだ発行していません」+「専用URLを発行」 |
| 有効 | ハッシュあり、期限が今より後 | ログインして `/me` へ | 「発行済み(有効期限 …)」+「再発行」「無効にする」 |
| 期限切れ | ハッシュあり、期限が今以前 | 「このリンクは使えません」 | 赤い「期限切れ」+「再発行」「無効にする」 |

- 管理者は、どの状態でも専用URLを持ちません
- 無効化しても、すでにログイン中の画面はログアウトかセッション切れ(30 分)まで使えます(対応しないと決定済み)

### 4.3 パスワードの状態(パスワードでログインする人)

```mermaid
stateDiagram-v2
    [*] --> パスワードなし: ユーザー登録(パスワード空欄)
    [*] --> 変更待ち: ユーザー登録(管理者が初期パスワードを設定)
    [*] --> 通常: 起動時に最初の管理者を作成
    パスワードなし --> 変更待ち: 管理者が設定 / 仮パスワードを発行
    変更待ち --> 通常: 本人がパスワードを変更
    通常 --> 変更待ち: 管理者が設定 / 仮パスワードを発行
    通常 --> 通常: 本人がパスワードを変更
    通常 --> 変更待ち: 起動時の復旧(APP_ADMIN_PASSWORD_RESET)
```

| 状態 | DB(`users`) | ログイン | ログイン後 |
|---|---|---|---|
| パスワードなし | `password_hash` が NULL | できない | — |
| 変更待ち | ハッシュあり、`password_change_required = true` | できる | パスワード変更画面以外は開けない(API は 403) |
| 通常 | ハッシュあり、`password_change_required = false` | できる | 通常どおり |

- 管理者が **自分自身** のパスワードを編集画面で設定した場合は、「変更待ち」にはなりません
- 専用URL方式の新入社員は、パスワードを使いません(この図の対象外)

### 4.4 タスクの状態

```mermaid
stateDiagram-v2
    [*] --> 有効: 登録(初期値は有効)
    有効 --> 無効: 編集で「有効」を外す
    無効 --> 有効: 編集で「有効」を付ける
    有効 --> [*]: 削除(割り当ても削除)
    無効 --> [*]: 削除(割り当ても削除)
```

- 無効のタスクは新しく割り当てられません。すでに割り当てた分はそのまま残ります

## 5. ER 図

```mermaid
erDiagram
    users ||--o{ task_assignments : "割り当てられる"
    tasks ||--o{ task_assignments : "割り当てられる"
    tasks ||--o{ task_checklist_items : "サブ項目を持つ"
    task_assignments ||--o{ assignment_checks : "チェックされる"
    task_checklist_items ||--o{ assignment_checks : "チェックされる"

    users {
        BIGSERIAL id PK
        VARCHAR name "氏名(必須)"
        VARCHAR email UK "メールアドレス(必須。大文字小文字を区別せず一意)"
        VARCHAR department "部署"
        DATE joined_on "入社日"
        VARCHAR password_hash "BCrypt。NULL=パスワードなし"
        VARCHAR role "ADMIN / MEMBER"
        BOOLEAN password_change_required "変更待ち"
        VARCHAR access_token_hash UK "専用URLの鍵の SHA-256"
        TIMESTAMPTZ access_token_expires_at "専用URLの有効期限"
        TIMESTAMPTZ created_at
        TIMESTAMPTZ updated_at
    }
    tasks {
        BIGSERIAL id PK
        VARCHAR title "タイトル(必須、200 文字)"
        TEXT description "説明(URL はリンクになる)"
        BOOLEAN active "有効"
        INTEGER sort_order "表示順"
        TIMESTAMPTZ created_at
        TIMESTAMPTZ updated_at
    }
    task_assignments {
        BIGSERIAL id PK
        BIGINT user_id FK "削除時は連鎖削除"
        BIGINT task_id FK "削除時は連鎖削除"
        VARCHAR status "NOT_STARTED / IN_PROGRESS / DONE"
        DATE due_date "期限"
        TIMESTAMPTZ completed_at "完了日時"
        TIMESTAMPTZ created_at
        TIMESTAMPTZ updated_at
    }
    task_checklist_items {
        BIGSERIAL id PK
        BIGINT task_id FK "削除時は連鎖削除"
        VARCHAR label "項目名(必須、200 文字)"
        INTEGER sort_order "表示順"
        TIMESTAMPTZ created_at
        TIMESTAMPTZ updated_at
    }
    assignment_checks {
        BIGSERIAL id PK
        BIGINT assignment_id FK "削除時は連鎖削除"
        BIGINT item_id FK "削除時は連鎖削除"
        TIMESTAMPTZ checked_at "チェックした時刻"
    }
```

- `task_assignments` は `(user_id, task_id)` の組み合わせが一意(同じ人に同じタスクは 1 回だけ)
- `assignment_checks` は `(assignment_id, item_id)` の組み合わせが一意(行があれば「チェック済み」)

## 6. シーケンス図

### 6.1 専用URLの発行と利用

```mermaid
sequenceDiagram
    actor 管理者
    actor 新入社員
    participant アプリ
    participant DB

    管理者->>アプリ: 「専用URLを発行」(POST /users/{id}/access-link)
    アプリ->>アプリ: 32 バイトの乱数(鍵)を作る
    アプリ->>DB: 鍵の SHA-256 と有効期限を保存
    アプリ-->>管理者: ユーザー詳細へ移動し、URL を 1 回だけ表示
    管理者->>新入社員: URL を渡す(アプリの外)
    新入社員->>アプリ: URL を開く(GET /join/{鍵})
    アプリ->>DB: 鍵の SHA-256 で検索
    alt 見つかり、期限内で、新入社員
        アプリ->>アプリ: ログイン状態にする(セッション ID を変更)
        アプリ-->>新入社員: マイページ(/me)へ移動
    else 見つからない・期限切れ
        アプリ-->>新入社員: 「このリンクは使えません」(404)
    end
```

### 6.2 初回ログイン時のパスワード変更

```mermaid
sequenceDiagram
    actor 管理者A
    actor 管理者B
    participant アプリ
    participant DB

    管理者A->>アプリ: 管理者B を初期パスワード付きで登録
    アプリ->>DB: パスワードのハッシュ、変更待ち = true
    管理者B->>アプリ: 初期パスワードでログイン
    管理者B->>アプリ: ダッシュボードを開く(GET /)
    アプリ->>DB: 変更待ちか確認
    アプリ-->>管理者B: パスワード変更画面へ移動
    管理者B->>アプリ: 現在のパスワード・新しいパスワードを送る
    アプリ->>DB: 新しいハッシュを保存、変更待ち = false
    アプリ-->>管理者B: ダッシュボードへ移動
```

### 6.3 パスワードを忘れたとき

```mermaid
sequenceDiagram
    actor 管理者A
    actor 管理者B
    participant アプリ
    participant DB

    alt ほかに管理者がいる
        管理者A->>アプリ: 管理者B の詳細で「パスワードをリセット」
        アプリ->>アプリ: 12 文字の仮パスワードを作る
        アプリ->>DB: ハッシュを保存、変更待ち = true
        アプリ-->>管理者A: 仮パスワードを 1 回だけ表示
        管理者A->>管理者B: 仮パスワードを伝える(アプリの外)
        管理者B->>アプリ: 仮パスワードでログイン → 変更画面で変更(6.2 と同じ)
    else 管理者が 1 人だけ
        管理者B->>アプリ: .env に APP_ADMIN_PASSWORD_RESET=true を書いて再起動
        アプリ->>DB: APP_ADMIN_PASSWORD のハッシュを保存、変更待ち = true
        アプリ->>アプリ: 「設定を外してください」と警告をログに出す
        管理者B->>アプリ: .env のパスワードでログイン → 変更
        管理者B->>アプリ: 設定を外して再起動
    end
```

## 8. 画面項目定義(入力チェック)

### 8.1 タスク登録・編集

| 項目 | 必須 | ルール | エラーメッセージ |
|---|---|---|---|
| タイトル | ○ | 前後の空白を除いて 1〜200 文字 | タイトルを入力してください / タイトルは200文字以内で入力してください |
| 説明 | | 自由(空欄可)。`http(s)://` の URL は画面でリンクになる | — |
| 有効 | | チェックボックス(初期値: 有効) | — |

### 8.2 ユーザー登録・編集

| 項目 | 必須 | ルール | エラーメッセージ |
|---|---|---|---|
| 氏名 | ○ | 100 文字まで | 氏名を入力してください / 氏名は100文字以内で入力してください |
| メールアドレス | ○ | メールの形式、255 文字まで、ほかの人と重複不可(大文字小文字は区別しない)。前後の空白は除く | メールアドレスを入力してください / メールアドレスの形式が正しくありません / メールアドレスは255文字以内で入力してください / このメールアドレスは既に登録されています |
| 部署 | | 100 文字まで(空欄可) | 部署は100文字以内で入力してください |
| 役割 | ○ | 管理者 / 新入社員。自分自身は管理者から変えられない | 役割を選択してください / 自分の役割は管理者から変更できません |
| パスワード | | 入力した場合のみ 8〜72 文字。編集で空欄なら今のまま | パスワードは8文字以上で入力してください / パスワードは72文字以内で入力してください |
| 入社日 | | 日付 | 日付の形式が正しくありません |

### 8.3 パスワード変更

| 項目 | 必須 | ルール | エラーメッセージ |
|---|---|---|---|
| 現在のパスワード | ○ | 今のパスワードと一致 | 現在のパスワードを入力してください / 現在のパスワードが正しくありません |

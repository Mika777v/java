## 1. 目的

新入社員・中途入社者が入社後に行う手続きや準備(PC のセットアップ、アカウント登録、規則の確認など)を **タスク** として配り、
**誰がどこまで終わっているか** を管理者がひと目で確認できるようにする。

### 解決したいこと

| 今までの困りごと | このシステムでどうなるか |
|---|---|
| やることの一覧が人によってバラバラ | 共通のタスク一覧(ひな形)を管理者が作り、そこから割り当てる |
| 誰がどこまで終わったか分からない | ユーザーごとの完了率・期限切れ件数を一覧とダッシュボードで表示 |
| 期限を過ぎても気づかない | 期限切れを赤く表示し、ダッシュボードで「フォローが必要な人」を表示 |
| 新入社員にアカウントやパスワードを配るのが手間 | 専用URLを渡すだけで、新入社員は自分のタスクを見られる |

---

## 2. 利用者

| 役割 | 人数の想定 | すること |
|---|---|---|
| 管理者 | 1〜数人(人事・受け入れ担当) | タスクの作成、ユーザーの登録、タスクの割り当て、進捗の確認 |
| 新入社員 | 一度に数人〜十数人 | 自分に割り当てられたタスクを確認し、状態(未着手 / 対応中 / 完了)を変える |

---

## 3. 前提と制約

| 項目 | 内容 |
|---|---|
| 公開範囲 | **社内の限られた人だけが使う**(インターネットに広く公開しない) |
| 利用期間 | 1 人あたり入社後の数週間〜数か月。長期間使い続けるアカウントは想定しない |
| 規模 | ユーザーは数十人まで、タスクは数十件まで |
| 利用環境 | PC のブラウザ(Chrome / Edge など)。スマホは見られれば十分 |
| 言語 | 画面はすべて日本語 |
| 実行環境 | Docker(アプリ + PostgreSQL)。開発・確認は GitHub Codespaces と GitHub Actions |
| 認証情報 | パスワードなどをプログラムや資料に書かない。環境変数で渡す |

---

## 4. 業務の流れ

```
【管理者】                                        【新入社員】
① タスクのひな形を作る(1 回だけ)
② 新入社員をユーザーとして登録する
③ タスクを割り当てる(期限つき。まとめて割り当ても可)
④ 専用URLを発行して、本人に渡す  ──────────────→ ⑤ 専用URLを開く(パスワード不要)
                                                  ⑥ 自分のタスクを見て、状態を変えていく
⑦ ダッシュボード・ユーザー一覧で進み具合を確認  ←── (状態がすぐ反映される)
⑧ 期限切れの人をフォローする
```

## 5. 機能要件

番号(FR-xx)は、AI 向けの [spec.md](ai/spec.md) でテストとの対応を取るのに使います。

### 5.1 タスク(ひな形)

| ID | 要件 |
|---|---|
| FR-01 | 管理者はタスクを登録・編集・削除できる。項目はタイトル(必須・200 文字まで)、説明、有効 / 無効 |
| FR-02 | タスクの表示順を ↑ / ↓ で変えられる。新しいタスクは最後に追加される |
| FR-03 | 無効にしたタスクは新しく割り当てられない(すでに割り当てた分は残る) |
| FR-04 | タスクを削除すると、そのタスクの割り当ても削除される |
| FR-05 | 説明に書いた `http://` / `https://` の URL はリンクとして表示し、新しいタブで開く(社内 SSO への案内など)。それ以外の文字はそのまま文字として表示する |
| FR-06 | タスクに **サブ項目**(チェックボックス)を持てる(例: 「スマホにアプリを入れる」→ Teams、SSO ログインアプリ)。管理者はタスクの編集画面で追加・削除する(名前は必須・200 文字まで)。追加・削除は、すでに割り当てた人にも反映される |

### 5.2 ユーザー

| ID | 要件 |
|---|---|
| FR-10 | 管理者はユーザーを登録・編集・削除できる。項目は氏名(必須)、メールアドレス(必須・重複不可・大文字小文字は区別しない)、部署、入社日、役割(管理者 / 新入社員) |
| FR-11 | ユーザーを削除すると、その人の割り当ても削除される |
| FR-12 | 管理者は、自分自身を削除したり、自分の役割を新入社員に変えたりできない(管理者がいなくなるのを防ぐ) |

### 5.3 割り当てと進捗

| ID | 要件 |
|---|---|
| FR-20 | 管理者はユーザーにタスクを 1 件ずつ(期限つき)、または有効なタスクをまとめて割り当てられる |
| FR-21 | 同じ人に同じタスクは 1 回しか割り当てられない |
| FR-22 | 割り当てごとに状態を 未着手 / 対応中 / 完了 で管理する。完了にすると完了日時を記録し、完了から戻すと消す |
| FR-23 | 期限を過ぎて完了していないものを「期限切れ」として赤く表示する。「今日」は日本時間で判断する |
| FR-24 | ユーザー一覧に、完了数 / 割り当て数・完了率・期限切れ件数を表示する。部署と進捗(未完了あり・期限切れあり・すべて完了・未割り当て)で絞り込める |
| FR-25 | ダッシュボード(管理者のトップページ)に、全体の完了率、状態ごとの件数、期限切れ件数、フォローが必要な人(期限切れの多い順)、7 日以内に期限が来るタスクを表示する |
| FR-26 | 新入社員はマイページでサブ項目を 1 つずつチェックできる。1 つでもチェックすると「対応中」、全部チェックすると「完了」に自動でなる(完了の後で外すと「対応中」に戻る)。管理者はユーザー詳細で、項目ごとのチェック状況(例: 2 / 3)を見られる |

### 5.4 ログインと権限

| ID | 要件 |
|---|---|
| FR-30 | 管理者はメールアドレスとパスワードでログインする |
| FR-31 | 新入社員は、管理者が発行した **専用URL** を開くだけでログインできる(パスワード不要) |
| FR-32 | 専用URLは推測できないこと。発行した直後に 1 回だけ表示し、あとから表示できない。有効期限は 60 日(設定で変更可) |
| FR-33 | 専用URLは再発行(古い URL は使えなくなる)と無効化ができる。管理者には発行できない |
| FR-34 | 設定で、新入社員もパスワードでログインする方式に切り替えられる(パスワード機能は削除しない) |
| FR-35 | 新入社員が見られるのは自分のマイページだけ。ほかの人のデータや管理者の画面は見られない |
| FR-36 | パスワードでログインする人は、自分のパスワードを変更できる(現在のパスワードの入力が必要。8〜72 文字) |
| FR-37 | 管理者がほかの人に設定したパスワードは、本人が最初にログインしたときに変更するまで、ほかの画面を使えない |
| FR-38 | パスワードを忘れたとき: ほかの管理者が仮パスワードを発行できる(1 回だけ表示、変更必須)。管理者が 1 人しかいない場合は、起動時の設定で最初の管理者のパスワードを戻せる |
| FR-39 | 起動したときに管理者が 1 人もいなければ、設定(環境変数)の値で最初の管理者を作る |

### 5.5 そのほか

| ID | 要件 |
|---|---|
| FR-40 | エラー(ページがない・権限がない・システムエラー)は日本語の画面で表示し、内部の詳しい情報は出さない |
| FR-41 | 外部から稼働状態を確認できる(ヘルスチェック。正常なら UP、DB に接続できなければ DOWN) |
| FR-42 | 管理者向けに、タスクを読み書きする REST API(JSON)を用意する |

## 6. 非機能要件

| ID | 分類 | 要件 |
|---|---|---|
| NFR-01 | セキュリティ | パスワードはそのまま保存せず、元に戻せない形(BCrypt)で保存する。専用URLも、元に戻せない形(SHA-256)だけを保存する |
| NFR-02 | セキュリティ | 画面のフォームは、なりすまし送信(CSRF)を防ぐ |
| NFR-03 | セキュリティ | 利用者が入力した文字は、画面で HTML として動かない(説明欄のリンク以外) |
| NFR-04 | セキュリティ | パスワード・認証情報をプログラム・資料・ログに書かない。CI では毎回ランダムな値を使い、ログでは隠す |
| NFR-05 | 運用 | 起動は Docker で 1 コマンド(Codespaces では自動)。DB の作成と初期データは自動 |
| NFR-06 | 運用 | プロキシの裏(Codespaces など)でも画面移動が正しく動く |
| NFR-07 | 品質 | 変更のたびに自動テストと Docker での動作確認を GitHub Actions で実行し、両方通らないと `master` にマージできない(ドキュメントだけの変更は省略) |
| NFR-08 | 性能 | 3 章の規模で、画面がすぐに表示される(特別な性能対策は不要) |
| NFR-09 | 保守 | 初めて Java を学ぶ人でも読めるよう、標準的な書き方にする。AI 向けの開発メモ(`docs/ai/`)を最新に保つ |

## 7. 対象外(やらないこと)

検討したうえで、今回は作らないと決めたものです。

| 項目 | 理由 |
|---|---|
| 専用URLを無効にしたら、ログイン中の画面もすぐ使えなくする | 公開しない前提なので影響が小さい。今はログアウトか 30 分操作がないと切れる |
| ユーザー・割り当ての REST API | 連携するシステム(人事システム・チャット通知など)がまだない。必要になったら検討 |
| メール送信(専用URLの送付、パスワード再設定メール) | 送信用メールサーバーと公開されたサーバーが必要。将来の候補 |
| 一覧のページ分け | 3 章の規模では不要 |
| 画面の作り込み(スマホ対応、画面フレームワーク) | 今の使い勝手で問題ない(オーナー確認済み) |

## 8. 用語

| 用語 | 意味 |
|---|---|
| タスク | 入社時にやることのひな形(全員共通) |
| 割り当て | あるユーザーにタスクを配ったもの。状態・期限・完了日時を持つ |
| 期限切れ | 期限が今日より前で、まだ完了していない割り当て |
| 専用URL | 新入社員ごとに発行する、パスワードなしでログインできるリンク |
| 仮パスワード | 管理者が発行する一時的なパスワード。ログイン後に変更が必要 |
| ダッシュボード | 管理者のトップページ。全体の進み具合をまとめて表示 |
| マイページ | 新入社員のページ。自分のタスクだけを表示 |

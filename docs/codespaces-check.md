# Codespaces での動作確認手順

PR をマージしたあと、アプリが正しく動くかを GitHub Codespaces で確認するための手順です。
上から順に進めると、ひととおりの機能を確認できます(所要時間: 起動 3 分 + 確認 10 分ほど)。

## 1. 準備(最新の状態で起動する)

### 新しく Codespace を作る場合

1. GitHub のリポジトリ画面で「Code → Codespaces → Create codespace on master」
2. 2〜3 分待つと、DB とアプリが自動で起動し、ブラウザでアプリが開きます

### 今ある Codespace を使う場合

ターミナルで次を実行します。

```bash
git checkout master && git pull
bash .devcontainer/start-app.sh
```

### 管理者のログイン情報

- 起動の最後に「Ready」と、管理者のメールアドレス・パスワードが表示されます
- 見逃したときは `cat onboarding-progress-system/.env` で確認できます
- 以前に管理者のパスワードを画面から変更した場合は、`.env` の値ではなく **変更後のパスワード** を使います
  (忘れた場合は 4 章の「管理者のパスワードを忘れたとき」)

## 2. 確認チェックリスト

| 4 | 「ユーザー」→「鈴木 一郎」を開き、タスクを割り当てて状態を変える | 進捗バーと「完了数 / 割り当て数」が変わる | ☐ |

自分の GitHub アカウントでログインすれば開けます。ほかの人に開いてもらうには、Ports タブでポート 8080 を Public にします。

## 3. うまくいかないとき

| 症状 | 対処 |
|---|---|
| ボタンを押すと「localhost 接続が拒否されました」になる | 古いバージョンの不具合(#24 で修正済み)。1 章の手順で最新の master にして起動し直す |
| 「One second, just getting your codespace ready」のまま進まない | タブを閉じて Ports タブから開き直す。だめなら 8080 の転送を止めて追加し直す、別のブラウザで開く |
| 画面が 401 / 502 になる | 起動途中のことが多いので、1 分ほど待ってから Ports タブ(地球のアイコン)で開き直す |
| 「Ready」が出ない・エラーになる | 下のコマンドの結果を AI に貼って相談する |
| ログインできない | `.env` のパスワードか、画面で変更したあとのパスワードかを確認する。ログからコピーすると時刻などが混ざるので、メールアドレスは手で入力する。忘れたら 4 章 |

原因を調べるコマンド(表示をそのまま貼ると原因を調べやすくなります):

```bash
cd onboarding-progress-system
docker compose ps
docker compose logs --tail 50 app
```

## 4. 管理者のパスワードを忘れたとき

- **ほかに管理者がいる場合**: その人がユーザー詳細画面で「パスワードをリセット」し、仮パスワードを教えてもらう
- **管理者が 1 人だけの場合**:
  1. `onboarding-progress-system/.env` に `APP_ADMIN_PASSWORD_RESET=true` の 1 行を追加
  2. `bash .devcontainer/start-app.sh` を実行
  3. `.env` の `APP_ADMIN_PASSWORD` でログインし、新しいパスワードに変更
  4. `.env` から追加した 1 行を消して、もう一度 `bash .devcontainer/start-app.sh`
     (消さないと、起動のたびにパスワードが戻ります)

## 5. 確認が終わったら

- Codespace は使わないと自動で停止しますが、すぐ止めたい場合は GitHub の「Codespaces」一覧から「Stop codespace」
- データを最初の状態(サンプルデータだけ)に戻したい場合は、次を実行してから `bash .devcontainer/start-app.sh`
  (**登録したタスク・ユーザー・進捗はすべて消えます**)

  ```bash
  cd onboarding-progress-system && docker compose down -v
  ```

## 未実装の機能

| 優先度 | 項目 | メモ |
|---|---|---|
| 高 | 初回ログイン時のパスワード変更の強制 | 次の PR で対応予定(設計了承済み)。管理者が別の管理者(`password` 方式なら新入社員も)にパスワードを設定したら「変更が必要」の目印を付け、目印のある人は `/me/password` 以外を開けないようにする |
| 中 | パスワードを忘れたときの再設定 | 今は管理者が編集画面で設定し直す運用。メール送信の仕組みはまだない。新入社員は専用URLの再発行で対応できる |
| 中 | ユーザー・割り当ての REST API | `/api/users`, `/api/users/{id}/assignments` など。他システム連携が必要になったら。`TaskController` と同じ作り |
| 低 | ヘルスチェック(Spring Boot Actuator) | 導入すれば CI・Codespaces の起動待ちを `/actuator/health` にできる。公開範囲に注意 |
| 低 | 一覧のページ分け | 今は全件表示。ユーザーが数百人規模になったら検討 |

## 既知の課題・整理候補

| 項目 | メモ |
|---|---|
| ルートの `README.md` が 1 行だけ | 詳細は `onboarding-progress-system/README.md`。必要ならリンクを追加 |
| `show-sql: true` | 開発用のまま。本番運用するならログが多すぎるので切り替えを検討 |
| サンプルデータが本番 DB にも入る | V2・V4 は通常のマイグレーション。本番運用するなら分離を検討 |
| 専用URLを無効化してもログイン中のセッションは残る | セッションが切れる(既定 30 分操作なし)かログアウトするまで使える。すぐ止めたい場合は、リクエストごとに専用URLの有効性を確認する仕組みが必要 |
| Codespaces では新入社員が専用URLを開けない | ポート 8080 は初期設定で非公開。Public にするか、どこかのサーバーに置く必要がある |
| Codespaces のホストネットワーク回避策 | Docker 29 のコンテナ間通信の問題が直れば `docker-compose.codespaces.yml` は不要になる |

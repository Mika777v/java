# 利用ガイド — オンボーディング進捗管理システム

- 版: 1.0(2026-10-20。PR #38 時点の機能)
- 対象: このアプリを使う **管理者(人事・受け入れ担当)** と、その説明を受ける **新入社員**
- 関連: 起動・動作確認の手順は [codespaces-check.md](codespaces-check.md)、仕様の詳細は [requirements.md](requirements.md) / [design.md](design.md)

---

## 1. このアプリでできること(ひと言で)

新入社員に「入社してからやること(タスク)」を配り、**誰がどこまで終わったか** を管理者がひと目で確認できます。
新入社員はパスワードを覚える必要がなく、管理者から渡された **専用URL** を開くだけで自分のタスクを確認・更新できます。

```
管理者: タスクを用意 → 新入社員を登録 → タスクを割り当て → 専用URLを渡す → 進み具合を確認
新入社員:                                       専用URLを開く → 自分のタスクを進めて状態を変える
```

---

## 2. 使い始める前に

| 項目 | 内容 |
|---|---|
| 起動 | Codespaces では自動で起動します(数分)。ターミナルに `Ready: the app is running on port 8080.` と出たら使えます |
| 画面を開く | 「ポート」タブの 8080 の地球儀アイコン |
| 最初の管理者 | メールアドレス `admin@example.com`。パスワードはターミナルで `cat /workspaces/java/onboarding-progress-system/.env` の `APP_ADMIN_PASSWORD=` の後ろ |
| サンプルデータ | 最初からタスク 6 件と、ユーザー 3 人(山田・佐藤・鈴木)、割り当て 10 件が入っています。試すのに使ってください |
| 新入社員に URL を開いてもらうには | Codespaces のポート 8080 は初期設定で **自分だけが開ける(非公開)** 状態です。ほかの人に専用URLを開いてもらうには、「ポート」タブで 8080 を **Public** にします |

## 3. 管理者の使い方

### 3.1 ダッシュボード(トップページ)

ログインすると最初に表示されます。全体の様子がまとめて分かります。

- **全体の完了率**(完了した割り当て / すべての割り当て)と、未着手・対応中・完了の件数
- **フォローが必要な人**: 期限切れのタスクがある人を、期限切れの多い順に表示
- **期限が近いタスク**: 今日から 7 日以内が期限の、まだ終わっていないタスク

### 3.2 タスク(ひな形)を用意する — 「タスク」メニュー

全員に共通の「やることリスト」です。最初に一度作っておけば、新入社員が来るたびに割り当てるだけです。

| やりたいこと | 操作 |
|---|---|
| 追加する | 「新規登録」→ タイトル(必須・200 文字まで)、説明、有効 を入れて登録 |
| 直す | 一覧の「編集」 |
| 並べ替える | 一覧の ↑ / ↓(この順番でマイページにも並びます) |
| 使わなくする | 編集で「有効」を外す(新しく割り当てられなくなる。すでに割り当てた分は残る) |
| 消す | 一覧の「削除」(**割り当ても進み具合も一緒に消えます**。記録を残したいなら「有効」を外すほうが安全です) |

**説明欄のリンク:** 説明に `https://...` で始まる URL を書くと、画面ではリンクになり、新しいタブで開きます(社内 SSO や手順書への案内に使えます)。

**サブ項目(チェックボックス):** 1 つのタスクの中に細かい作業があるときに使います(例: 「スマホにアプリを入れる」→ Teams、SSO ログインアプリ)。

- タスクを登録した後、**編集画面の下の「サブ項目」欄** で追加・削除します
- 追加・削除は、すでに割り当てた人にもすぐ反映されます
- 新入社員が全部チェックすると、そのタスクは自動で「完了」になります

### 3.3 新入社員を登録する — 「ユーザー」メニュー

「新規登録」で、氏名(必須)、メールアドレス(必須)、部署、入社日、役割を入れます。

- 新入社員の役割は「新入社員」にします。**パスワードは空欄のままで OK** です(専用URLでログインするため)
- メールアドレスは、大文字・小文字の違いだけの重複も登録できません
- 管理者を増やすときは、役割を「管理者」にして初期パスワード(8〜72 文字)を入れます。その人は最初のログインでパスワードの変更を求められます

### 3.4 タスクを割り当てる — ユーザー詳細

「ユーザー」一覧で名前の「詳細」を開き、画面の下の「タスクを割り当てる」を使います。

| やりたいこと | 操作 |
|---|---|
| 1 つずつ割り当てる | タスクと期限(任意)を選んで「割り当てる」 |
| まとめて割り当てる | 期限(任意)を選んで「有効なタスクをすべて割り当てる」(まだ割り当てていない有効なタスクが全部入る) |
| 状態を直す | 表の「状態」を選んで「変更」(新入社員の代わりに直したいとき) |
| 外す | 「割り当て解除」(その人の進み具合も消えます) |

同じ人に同じタスクは 1 回だけ割り当てられます。

### 3.5 専用URLを発行して渡す — ユーザー詳細

1. 詳細画面の「専用URLを発行」を押す
2. 黄色の枠に URL が **1 回だけ** 表示されるので、コピーしてチャットやメールで本人に渡す
3. 本人がその URL を開くと、パスワードなしで自分のマイページが開く

| 知っておくこと | 内容 |
|---|---|
| 有効期限 | 発行から 60 日 |
| もう一度表示したい | できません(安全のため、アプリも URL を覚えていません)。「再発行」してください |
| 再発行 | 新しい URL になり、**古い URL は使えなくなります** |
| 無効にする | 「無効にする」で URL が使えなくなります(すでに開いている画面は、ログアウトするか 30 分操作がないと切れます) |

### 3.6 進み具合を確認する

| 画面 | 分かること |
|---|---|
| ダッシュボード | 全体の完了率、フォローが必要な人、期限が近いタスク |
| ユーザー一覧 | 一人ずつの「完了数 / 割り当て数」・完了率・期限切れの件数。**部署** と **進み具合**(未完了あり・期限切れあり・すべて完了・未割り当て)で絞り込める |
| ユーザー詳細 | タスクごとの状態・期限・完了日時、サブ項目のチェック状況(例: 「サブ項目 2 / 3」) |

**期限切れ** は、期限が今日(日本時間)より前で、まだ完了していないタスクです。赤い印で表示されます。

### 3.7 パスワードのこと(管理者)

| やりたいこと | 操作 |
|---|---|
| 自分のパスワードを変える | 画面右上の「パスワード変更」 |
| ほかの管理者がパスワードを忘れた | その人の詳細画面で「パスワードをリセット」→ 仮パスワード(12 文字)が 1 回だけ表示されるので本人に伝える。本人は最初のログインで変更する |
| 管理者が 1 人しかいなくて忘れた | `docs/codespaces-check.md` の「4. 管理者のパスワードを忘れたとき」の手順で、起動時の設定から戻す |

## 4. 新入社員の使い方

管理者から受け取った **専用URL** を開くだけです(パスワードは不要)。

1. URL を開くと、自分の **マイページ** が表示されます。上の進捗バーで、どこまで終わったか分かります
2. タスクを進めたら、「状態」を選んで「変更」を押します(未着手 → 対応中 → 完了)
3. タスクの下に **サブ項目**(☐ が並んだもの)があれば、終わったものから押します
   - 1 つでもチェックすると「対応中」、全部チェックすると自動で「完了」になります
   - 間違えて押したら、もう一度押すとチェックが外れます
4. 説明に書かれたリンクは、新しいタブで開きます

| 困ったとき | 対処 |
|---|---|
| 「このリンクは使えません」と出る | 期限切れか、管理者が再発行・無効にした URL です。管理者に新しい URL をもらってください |
| ほかの人のタスクを見たい | 見られません(自分のタスクだけが表示されます) |
| しばらくして開いたらログイン画面になった | 30 分操作しないとログアウトされます。もう一度専用URLを開いてください |

## 5. できること・できないこと

### できること

| 分類 | できること |
|---|---|
| タスク | 登録・編集・削除・並べ替え、有効 / 無効の切り替え、説明の URL をリンク表示、サブ項目(チェックボックス) |
| ユーザー | 登録・編集・削除、部署・入社日の管理、役割(管理者 / 新入社員) |
| 割り当て | 1 件ずつ・まとめて割り当て、期限の設定、状態の変更、割り当て解除 |
| 進捗の確認 | ダッシュボード、ユーザー一覧(完了率・期限切れ・絞り込み)、ユーザー詳細 |
| ログイン | 新入社員は専用URL(パスワードなし)、管理者はメールアドレスとパスワード。設定で新入社員もパスワード方式にできる |
| 安全のための仕組み | 新入社員は自分のデータしか見られない、管理者の画面は開けない。パスワードと専用URLは元に戻せない形で保存。削除・役割変更された管理者はすぐにログアウトされる |
| 外部連携 | タスクの読み書きができる REST API(管理者のみ、`/api/tasks`) |
| 運用 | ヘルスチェック(`/actuator/health`)、Docker で 1 コマンド起動、Codespaces で自動起動 |

### できないこと(今の制限)

| できないこと | 代わりの方法 / 今後 |
|---|---|
| 専用URLや通知を **メールで自動送信** する | URL は管理者がコピーしてチャット・メールで渡す。メール送信は将来の候補(送信用サーバーが必要) |
| 新入社員が **自分でパスワードを再設定** する | 専用URL方式ではパスワードを使わない。パスワード方式の場合は管理者がリセットする |
| 専用URLを **あとから表示** する | 再発行する |
| 専用URLを無効にした瞬間に、開いている画面を閉じる | ログアウトするか 30 分操作がないと切れる(公開しない前提のため対応しない) |
| タスクごとに **担当の管理者** を決める・**コメント** を書く | なし |
| サブ項目の **並べ替え・名前の変更** | 削除して追加し直す。並べ替えは将来の候補 |
| **親子タスク**(子ごとに期限・状態を持つ) | サブ項目で代用。必要になったら検討(優先度 低) |
| 期限切れの **お知らせ**(メール・チャット) | ダッシュボードの「フォローが必要な人」で確認する |
| ユーザー・割り当ての **REST API**、人事システムとの自動連携 | 画面から操作する。連携先ができたら検討 |
| **CSV などでの一括登録・出力** | 画面から 1 件ずつ登録する |
| 一覧の **ページ分け**(数百人規模) | 今は全件表示(数十人を想定) |
| **スマホ向け** の画面 | スマホのブラウザでも見られるが、PC 向けの作り |
| **削除したデータの復元** | できない。消す前に確認画面が出るので注意する。タスクは「有効」を外す運用がおすすめ |
| 操作の **履歴(誰がいつ何を変えたか)** | 完了日時だけ記録。そのほかの履歴はなし |

## 6. 運用のヒント

- **タスクのひな形は最初にしっかり作る**: 並び順はマイページの表示順になります。よく使う順・やる順に並べておくと、新入社員が迷いません
- **細かい作業はサブ項目に**: タスクを増やしすぎると一覧が長くなります。同じ期限で終わらせる作業はサブ項目にまとめると見やすくなります
- **期限は必ず入れる**: 期限がないタスクは「期限切れ」にならないので、ダッシュボードのフォロー対象に出ません
- **使わなくなったタスクは削除より「無効」**: 削除すると、過去に割り当てた人の記録も消えます
- **専用URLはチャットの個別メッセージで**: URL を知っている人は誰でもその新入社員として開けます。共有のチャンネルには貼らないでください
- **サンプルデータ**: 試し終わったら、サンプルのユーザー(山田・佐藤・鈴木)は削除して構いません。サンプルのタスクも、使わないものは削除か「無効」にしてください

## 7. よくある質問

| 質問 | 答え |
|---|---|
| 新入社員にパスワードを決めてもらう方式にできる? | できます。起動時の設定 `APP_MEMBER_LOGIN=password` で切り替わります(管理者がユーザーの編集画面で初期パスワードを設定し、本人が最初のログインで変更) |
| 専用URLの有効期限を変えたい | 起動時の設定 `APP_ACCESS_LINK_VALID_DAYS`(日数)で変えられます |
| 管理者は何人でも作れる? | 作れます。ただし自分自身を削除したり、自分を新入社員に変えたりはできません(管理者がいなくなるのを防ぐため) |
| 「今日」はどこの時間? | 日本時間です(設定 `APP_TIME_ZONE` で変更可) |
| データはどこに保存される? | PostgreSQL のデータベースです。Codespaces を削除するとデータも消えます |

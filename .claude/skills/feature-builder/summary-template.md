# 実装後の要約のひな形(feature-builder 用)

実装が終わったら、オーナーに日本語でこの形で報告します。専門用語は少なめに、「なぜ」を一言添えます。

```markdown
## 何を作ったか
(1〜3 行。利用者から見て何ができるようになったか)

## 変更したファイル
| 種類 | ファイル | 内容 |
|---|---|---|
| マイグレーション | `V10__xxx.sql` | |
| Entity / Repository / Service | | |
| 画面(Controller・テンプレート) | | |
| テスト | | 追加 n 件(正常系・入力エラー・404・権限) |
| ドキュメント | | |

## 設計で決めたこと(と理由)
- 例: 「お知らせ」は管理者だけが登録できる(新入社員に編集させる要件がないため)

## 確認したこと
- `mvn -B test`: 全 n 件成功(前回から +m 件)
- 画面の確認: (Docker で起動して確認した手順)
- わざと壊して、新しいテストが失敗することを確認: (どこを壊したか)

## Codespaces での確認方法(オーナー向け)
1. ...
2. ...

## 気づいたこと(今回は直していない)
- (関係ない問題を見つけたら。直すかどうかはオーナーが決める)

## 次の一手
- 「PRを作って」と言っていただければ PR を作ります
```

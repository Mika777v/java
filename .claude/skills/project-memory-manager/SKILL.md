# project-memory-manager — 現状把握とドキュメント管理

このリポジトリの「記憶」は `docs/` にあります。このスキルは、コードとドキュメントのずれを見つけて直し、
次にやることを提案します。**実装の前に必ずこの調査を行います**(feature-builder などから呼ばれる場合も同じ)。

## 前提(必ず守る)

- 構成: Spring Boot 3.3 + PostgreSQL 15 + Flyway + Thymeleaf(詳細は `docs/ai/project-context.md`)
- 情報の優先順位: **`docs/ai/` > `docs/current-status.md` > そのほかの `docs/`**。ただし最終的な正解はコード。
  ドキュメントとコードが食い違ったら、コードを確かめてドキュメントを直す(コードは勝手に直さない)
- `master` に直接 push しない。作業ブランチで変更し、オーナーが「PRを作って」と言ったら PR を作る
- パスワード・認証情報をドキュメントに書かない(`.env` の中身やログに出たパスワードも)
- 説明は日本語で、専門用語を使いすぎない

## 手順

### 1. 事実を集める(コードを変えない)

```bash
.claude/skills/project-memory-manager/scripts/survey.sh
```

ブランチ、最近マージした PR、マイグレーション、クラス、URL、テンプレート、テストの数、
ドキュメントに書いてある数字、技術的負債のサイン(Controller が Repository を直接使っている、など)が出ます。

### 2. ドキュメントを読む

| 読むもの | 何を確かめるか |
|---|---|
| `docs/ai/project-context.md` | 構成・環境変数・関連ドキュメント |
| `docs/ai/spec.md` | 要件 ID(FR / NFR)、壊してはいけないルール(INV)、状態遷移 |
| `docs/ai/architecture.md` | クラス一覧・URL 一覧・セキュリティ |
| `docs/ai/database.md` | マイグレーション一覧・テーブル定義・サンプルデータ |
| `docs/ai/backlog.md` | ロードマップ(未実装)・既知の課題・技術的負債・完了済み |
| `docs/current-status.md` | 人向けの現状レポート(版数・変更履歴・各章) |

どの情報がどのファイルのどの章にあるかは [doc-map.md](doc-map.md) にまとめています。

### 3. ずれを洗い出す

1 の結果と 2 のドキュメントを比べ、次の表を作ります。

| ドキュメント | 書いてあること | 実際(コード) | 直し方 |
|---|---|---|---|

よくあるずれ: テストの件数、マイグレーションの追加漏れ、URL・クラスの追加漏れ、backlog の「完了済み」への移し忘れ、
current-status の版数・変更履歴の更新漏れ。

### 4. 技術的負債を整理する

survey.sh の「Technical debt signals」と、必要なら `spring-boot-architect` の `layer-check.sh` の結果から、
`docs/ai/backlog.md` の「技術的負債」の表を更新します(種類 / 場所 / 困ること / 対応案 / 優先度)。
優先度は「困ること」の大きさで決めます。見た目だけの問題は「低」。

### 5. 次の推奨タスクを決める

`docs/ai/backlog.md` の「ロードマップ」を、次の順で並べ直します。

1. 不具合・セキュリティの問題
2. オーナーが頼んだが未完了のもの
3. 技術的負債のうち、次の機能追加の邪魔になるもの
4. 未実装の機能(優先度の高い順)

「保留」「対応しない(オーナー判断)」と書いてあるものは、オーナーが言わない限り推奨しません。

### 6. ドキュメントを更新する(頼まれたとき、またはずれがあったとき)

- `docs/current-status.md`: 冒頭の調査日と版数(第N版 → 第N+1版)、「これまでの主な変更」に 1 行追加、該当する章
- `docs/ai/*.md`: 該当する表だけ。`backlog.md` は「最終更新」の日付も
- 機能の説明が変わったら `docs/requirements.md` / `docs/design.md` / `docs/design-diagrams.md` も
- ドキュメントだけの変更なら CI の `test` / `run-smoke` はスキップ扱いになる(テストは不要)
- 変更したら、作業ブランチにコミットして push する(コミットメッセージは英語の命令形)

## 報告の形

```
## 現状(1〜3 行)
## ドキュメントとコードのずれ(表。直したものには「修正済み」)
## 技術的負債(上位 3〜5 件。理由つき)
## 次の推奨タスク(上位 3 件。なぜそれが先か、規模の目安)
## 更新したファイル
```
